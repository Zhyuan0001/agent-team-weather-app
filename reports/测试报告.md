## 三、用例清单（按模块）

### 3.1 core/date_utils（31 用例，全部通过）
- `parse_date` 闰年通过：`2024-02-29` ✅
- `parse_date` 拒绝 13 种非法字符串：`2023-02-30`、`2023-02-29`（非闰年）、
  `2023-13-01`、`2023-00-10`、`2023-04-31`、`2023-1-1`、`2023-01-1`、`2023-1-01`、
  `2023/01/01`、`01-01-2023`、`abc`、`""`、空白 ✅
- `parse_date` 拒绝非字符串：`None`、`int`、`float`、`bool`、`list` ✅
- `today()` 返回 `date`；`max_supported_date() = today + 16` ✅
- `is_supported_range` 上下边界（含 `MIN_SUPPORTED_DATE-1` 拒绝、`today+17` 拒绝）、
  非日期返回 False、`datetime` 被接受 ✅

### 3.2 core/units（17 用例，16 通过 / 1 失败）
- `c_to_f`：0/100/-40/37/-10 ✅；`f_to_c`：32/212/-40/98.6 ✅；往返一致 ✅
- `unit_symbol` 未知回退 `°C`、`convert` 未知单位按摄氏度 ✅
- `format_temperature`：默认 1 位、负温 `-5.0 °C`、华氏 `212.0 °F`、取整 ✅
- ❌ **失败**：`format_temperature(-0.5, "C", 0)` 期望 `"0 °C"`，实际 `"-0 °C"`（负零，Bug B06）

### 3.3 core/formatting（31 用例，全部通过）
- 8 种状况 → 中文名/emoji 均非兜底值；具体值（晴/多云/雨/雪/雷阵雨）✅
- 未知状况兜底：标签 `"未知"`、emoji `"❓"`（含 `""`/`None`/`0`/`"SUNNY"`/`"typhoon"`）✅
- `source_label` 已知/未知/空串 ✅
- `render_record`：日期、状况、温度（C/F）、`62%`、`12.3 km/h`、来源 ✅

### 3.4 providers/offline（6 用例，全部通过）
- 同日多次调用**完全相等**（`__eq__`，20 次重复一致）✅
- `datetime` 归一化为 `date`；非日期抛 `ValueError` ✅
- 遍历整年（366 天）字段合法：湿度 ∈[0,100]、风速 ≥0、状况 ∈ `ALL_CONDITIONS`、
  来源 = `offline` ✅
- 温度落在「当月基准 ±4℃」构造区间 ✅

### 3.5 providers/open_meteo（36 用例，27 通过 / 9 失败）
- 正常 payload 解析（温度均值、状况、湿度、风速、来源、URL 分支、timeout 透传）✅
- 参数注入 `session` + `monkeypatch(requests.Session)` 两种伪造方式 ✅
- 超范围：早于 1940 / 超过 `today+16` → `DateOutOfRangeError`（且不发请求）✅
- 非日期类型 → `DateOutOfRangeError` ✅
- HTTP 500 / `requests.Timeout` / `ConnectionError` / 非法 JSON → `WeatherUnavailableError` ✅
- 字段名不符（温度键改名）→ `WeatherUnavailableError` ✅
- WMO 映射（0/2/3/45/48/51/61/71/80/95/未知/None）✅
- ❌ **失败 9 例**：
  - payload 非 dict / `None` → 期望 `WeatherUnavailableError`，实际 `AttributeError`（B01）
  - 温度为字符串 `"abc"` → 实际 `ValueError`（B01）
  - 湿度为字符串 `"abc"` → 实际 `ValueError`（B01）
  - 湿度缺字段 / 风速缺字段 / 湿度为 `null` → 期望报错，实际静默回填 `0`（B02）
  - 目标日期不在返回数组 → 期望报错，实际静默取首项并改写 `date`（B03）
  - WMO `1` → 期望 `sunny`，实际 `cloudy`（B07）

### 3.6 services/weather_service（10 用例，8 通过 / 2 失败）

  - 持续失败连续查询 2 次 → 期望只尝试在线 1 次，实际 2 次（B04 无负缓存）

## 六、结论

- 纯逻辑层（`core/`）质量高：日期严格校验、单位换算、状况映射、离线确定性**全部通过**，
  且架构约束（core 无 GUI/网络依赖）经静态测试确认符合 SPEC §5。
- 缺陷集中在 **`providers/open_meteo` 的解析健壮性** 与 **`services` 的降级完备性**：
  畸形响应会以 `AttributeError`/`ValueError` 穿透（破坏 SPEC F4「失败必降级」），
  关键字段缺失被静默回填为 0 并标注为「在线数据」（静默错误数据）。
- 13 个失败用例归纳为 **7 个 bug（高 2 / 中 3 / 低 2）**，详见 `bug清单.md`，
  需转交 CodeWriter 在 P4/P5 修复后回归本套用例。
