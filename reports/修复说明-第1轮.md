## 二、逐条修复说明

### B01 · 高 · 畸形响应抛非业务异常穿透，破坏「失败必降级」

- **改动文件:位置**：`weather_app/providers/open_meteo.py` → `_parse()`（原 152–195）；`weather_app/services/weather_service.py` → `get_weather()` 在线分支的 `except`。
- **修复做法**：
  1. **解析层归一化**：重写 `_parse`，对一切畸形数据统一抛 `WeatherUnavailableError`：
     - 顶层非 dict（含 `None`、`list`）→ `WeatherUnavailableError`（原名 `payload.get` 会抛 `AttributeError`）；
     - `daily` 缺失/非 dict、`time` 缺失/非序列/为空 → `WeatherUnavailableError`；
     - 温度/湿度/风速取值统一走新的 `to_float()`，对 `None`、`null`、不可解析字符串（如 `"abc"`）抛 `WeatherUnavailableError`（原 `float(...)` 会抛 `ValueError`）。
  2. **服务层兜底**：`get_weather` 的在线分支在保留 `except DateOutOfRangeError: raise`（不降级）之后，把捕获范围从仅 `WeatherUnavailableError` 扩展为 `(WeatherUnavailableError, AttributeError, ValueError, TypeError, KeyError)`，即上游任何「取不到数据」类异常都触发降级，满足 SPEC F4；`core` 侧异常类型不受影响。
- **对应用例**：`test_parse_non_dict_payload_raises_unavailable`、`test_parse_none_payload_raises_unavailable`、`test_parse_string_temperature_raises_unavailable`、`test_parse_string_humidity_raises_unavailable`、`test_parse_style_exception_should_degrade`。

### B02 · 高 · 湿度/风速关键字段缺失时静默回填 0

- **改动文件:位置**：`weather_app/providers/open_meteo.py` → `_parse()` 中 `humidity` / `wind_kph` 取值处。
- **修复做法**：删除 `value("relative_humidity_2m_mean", 0) or 0` 与 `value("wind_speed_10m_max", 0) or 0` 的静默回填；改用 `to_float()`，字段缺失、为 `null` 或不可解析时一律抛 `WeatherUnavailableError`，与温度字段策略对齐（错误数据优先降级，而非在「在线数据」标记下展示 0）。
- **对应用例**：`test_parse_missing_humidity_raises_unavailable`、`test_parse_missing_wind_raises_unavailable`、`test_parse_null_humidity_raises_unavailable`。

### B03 · 中 · 目标日期不在返回数组时静默取首项并改写 date

- **改动文件:位置**：`weather_app/providers/open_meteo.py` → `_parse()` 日期定位处（原 `except ValueError: index = 0`）。
- **修复做法**：删除退化为 `index = 0` 的容错；当 `times` 中找不到 `day.isoformat()` 时抛 `WeatherUnavailableError`（视为数据源异常），杜绝把其它日期的天气错配给目标日期。
- **对应用例**：`test_parse_date_not_in_times_raises_unavailable`。

### B04 · 中 · 在线失败后无负缓存，离线演示场景反复重试

- **改动文件:位置**：`weather_app/services/weather_service.py` → `__init__`、`clear_cache()`、`get_weather()`。
- **修复做法**：
  1. 新增实例状态 `self._online_failed_days: set[date]`（在线失败负缓存）；
  2. 在线查询抛「可降级异常」时把该日期写入负缓存；
  3. `get_weather(use_online=True)` 在尝试在线前先检查负缓存：命中则跳过在线、直接走离线（并置 `last_fallback=True`，界面仍提示「已自动降级」）；
  4. `clear_cache()` 同时清空负缓存，保证「清缓存后可重新尝试在线」（`test_clear_cache_forces_refetch` 语义不变）。
- **对应用例**：`test_repeated_offline_demo_should_not_retry_online_every_time`（修复后 online 调用 1 次、offline 调用 1 次）。

### B05 · 中 · 查询进行中按钮不禁用、无忙碌态

- **改动文件:位置**：`weather_app/ui/main_window.py` → `_on_query()`，并新增 `_set_querying()`。
- **修复做法**：`_on_query` 进入时将查询按钮置为禁用并把文案改为「查询中…」（`_set_querying(True)`），业务逻辑整体包在 `try/finally` 中，`finally` 恢复按钮可用与文案「查询天气」；无论成功、降级还是异常都不遗漏恢复。避免阻塞期间被重复点击。
- **对应用例**：`test_query_button_disabled_during_query`（查询中 `isEnabled() == False`）。

### B06 · 低 · 取整 0 位小数时出现负零显示 `-0 °C`

- **改动文件:位置**：`weather_app/core/units.py` → `format_temperature()`。
- **修复做法**：先 `round(value, decimals)` 再判断 `if rounded == 0: rounded = 0.0`，消除 IEEE 负零后再格式化，使 `format_temperature(-0.5, "C", 0)` 输出 `"0 °C"`；其余取值（正/负整数位、华氏转换）结果不变。
- **对应用例**：`test_format_temperature_zero_decimals_negative_value_should_not_be_negative_zero`。

### B07 · 低 · WMO 码 `1`（Mainly clear）被映射为「多云」

- **改动文件:位置**：`weather_app/providers/open_meteo.py` → `map_wmo_code()`。
- **修复做法**：拆开原 `if code in (1, 2): return CLOUDY`：`code == 1`（大部晴朗）→ `SUNNY`；`code == 2`（局部多云）→ `CLOUDY`，其余不变。
- **对应用例**：`test_map_wmo_code_1_mainly_clear_is_sunny`。
